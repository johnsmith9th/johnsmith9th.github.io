Two small tools that run on your own Windows PC

One keeps a project folder findable: it puts your own taxonomy on local files, then searches inside the text of Office and PDF documents. The other files finished downloads into an archive folder. Both run locally — no account, no sign-in, nothing uploaded.

Product 01

PMDir — local file tagging and full-text search

Register the project folders you already have, lay a tag scheme of your own over the file tree, turn tag conditions into queries, and go straight to the text inside Office and PDF documents. Entirely offline: no network, no collection, no upload.

  • No network, no telemetry, no account. The UI loads no remote fonts and no remote images.
  • Tags come in categories. Each category has a colour and a rank, can carry typed values, and can be made mutually exclusive.
  • Queries combine with AND / OR / NOT, and the hit count moves as you change a condition.
  • It searches inside documents. docx / xlsx / pptx / PDF / md / txt / csv, plus the legacy .doc / .xls / .ppt formats — without Office installed.
  • Sorting matches Windows Explorer: pinyin order and natural number order.
  • Tags survive copy and paste. The tags are still there afterwards.
  • It exports CSV, with protection against spreadsheet formula injection.
  • zip and 7z are built in, both ways (creating a 7z needs 7z.exe on your system).
  • Delete goes to the Recycle Bin. There is no permanent delete.
  • A damaged library or index repairs itself.
  • Three interface languages (Simplified Chinese, Traditional Chinese, English) and three themes (auto, light, dark).
  • Collapse view folds the whole window into a single horizontal bar.

The "Indexed N%" figure is honest: it counts how many files have had their text extracted, not the health of the index. When the index layer could not be opened, it reads "Index —".

Product 02

Download2 — files itself away when the download finishes

A 236 × 40 bar keeps an eye on your Downloads folder. When a file has finished downloading, it moves that file into an archive folder you choose, optionally into a subfolder named after the download date. It is not a download manager, and it does not speed anything up.

  • Seven conditions mean "this download finished": a quiet window (900 ms by default, 200–5000 ms), two consecutive samples with the same size and modification time, no live temporary path pointing at the file, a lock probe, a denylist of temporary extensions (.crdownload .part .download .partial .tmp .idmdownload .__partialdownload, ~$*), a size greater than zero, and not being part of the baseline that already existed at startup.
  • A half-finished file is never moved.
  • An existing file is never overwritten. (1) and (2) are appended, up to 999 — a Windows rename silently eats the target if it already exists.
  • A move on the same volume is two renames and copies zero bytes. Across volumes it falls back to a copy, and the source is deleted only after a byte-count check passes.
  • Crash-recoverable. An append-only pending.jsonl ledger and a pure-function replay table re-adopt half-finished moves on the next launch.
  • Some places it refuses to file into: inside the Downloads folder, a drive root, \Windows, and Program Files.
  • Corrupt settings are quarantined, never silently reset.
  • One window, total. Frameless, always on top, transparent, hidden from the taskbar — and every setting saves itself, so there is no Save button.
  • English and Chinese, in a light or a dark theme.

What it does not do: it has no download engine — no acceleration, no BT, no ED2K — no resume for interrupted downloads, no browser extension, no plugin system, no system tray icon, and no installer or auto-update: the release is a portable zip you unzip and run.
