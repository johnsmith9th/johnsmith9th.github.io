How to reach me

Email: johnsmith9th@yahoo.com

This is the only support channel: no phone line, no live chat, no forum. PMDir is a one-person project, and I do not promise a response time. I read everything that arrives; it can take a few days.

Please include in your message

  • the version number — shown on Settings → About;
  • which edition you are using: Microsoft Store, installer or portable;
  • your data location — the path shown on Settings → Data location;
  • what you clicked, what you expected, and what actually happened;
  • the log file for that day, attached from <data location>\logs\. Logs record the program's own steps only — they never contain your document text, and you can open one and check before sending it.
Please do not attach your database file (meta.sqlite) to a first message. It contains your file names and folder structure. A log plus a description is enough in most cases; if I really need the database, I will ask you first.

Frequently asked

Where exactly is my data?

Everything shown on Settings → Data location: data\ holds the database, index\ the full-text index, logs\ the logs. By default these sit next to the program itself. The Microsoft Store edition installs to a folder that is read-only for the app, so there it defaults to %APPDATA%\PMDir, and the Settings page says why. You can move it to any folder you have access to.

What survives an uninstall? How do I remove everything?

Microsoft Store edition: the Store does not run our uninstaller, so two locations remain and you delete them by hand: 

%APPDATA%\PMDir          database (data\meta.sqlite), full-text index, logs
%USERPROFILE%\.pmdir     per-library pre-start backups

Portable edition: delete the program folder. Installer edition: the uninstaller asks whether to keep backups and then removes the backup tree under ~\.pmdir; if you had pointed the data directory elsewhere, delete that yourself. Uninstalling never deletes the original files in your projects.

What does "Indexed N%" mean, and why does it never reach 100%?

That number counts how many files have had their text extracted; it is not a health check of the index itself. Below 100% usually means one of two things: some files have not been extracted yet (restarting the app continues the queue), or some files have no extractable text at all — archives, scanned images, or file types where automatic extraction is off. Neither is a fault.

If that field shows "Index —" instead of a percentage, the index layer could not be opened this run. Open Settings → Rebuild index and press Start rebuild. Most damage repairs itself at startup: a broken index directory is renamed and kept, then rebuilt, and the space that kept copy uses is yours to clean up.

Why do some archives need 7-Zip installed and others do not?

  • Reading and extracting zip / 7z uses built-in code — no extra software required;
  • Creating a 7z requires 7-Zip to be installed on your computer. If it is not, that menu entry simply does not appear (it is not a button that fails when you click it);
  • .rar is not supported, so no extract action is offered for rar files.

It asked me for a password while extracting — is something wrong?

No. When a protected archive does not expose its contents list, PMDir asks once for the password to decide where to put things; cancelling that dialog abandons the job. If extracted names collide with what is already there, it asks once how to resolve the clash — the answer is not remembered, so it will ask again next time.

Can it search inside old .doc / .xls / .ppt files?

Yes. Those Office 97-2003 formats are read by an engine included with PMDir; you do not need Office installed.

It says my library is damaged at startup.

PMDir then tries to recover automatically from the most recent local backup, kept under ~\.pmdir in a folder per library.

Is PMDir free?

Yes — freeware, with every feature unlocked. There is an optional "buy the author a coffee" page inside the app; it is entirely voluntary and nothing is limited if you skip it.
