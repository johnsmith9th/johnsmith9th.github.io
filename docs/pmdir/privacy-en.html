PMDir

Privacy Policy

Effective 2026-10-19 Applies to all PMDir versions

Language: English ｜ 中文

PMDir is a fully offline local file management tool. It does not use the network, does not collect anything and does not upload anything, and it has no accounts. Your file names, folder structure and indexed document text are written only to a database on your own disk.

1. Nothing leaves your computer

To be concrete, PMDir does not do any of the following:

  • no telemetry, no crash reports, no usage analytics;
  • no requests to any server, and no push notifications;
  • every style sheet and script the interface needs is compiled into the app — no remote fonts, no remote images, no third-party CDN resources;
  • no advertising SDK, no analytics SDK, no tracking code of any kind;
  • no sign-up and no sign-in, so there is no user profile for anyone to look up;
  • extracting document text, building the index and searching all happen on your machine — your document contents are never sent anywhere.

2. Where your data lives

All of PMDir's data sits in a directory you control, in three parts:

Directory What it holds
data\ The metadata database (meta.sqlite): the paths of the project folders you added, the names, sizes and modification times of the files it scanned, the tags you applied, and the text-extraction state of each file.
index\ The local full-text index used for content search. Deleting it only costs you a re-index; it never touches your original files.
logs\ Day-by-day run logs, written on your machine only and never sent anywhere automatically.

The root of those three directories defaults to the folder holding the program itself (portable layout: data\, index\ and logs\ next to pmdir.exe), and you can point it at any directory you have access to under Settings → Data location. The Microsoft Store edition installs into a folder that is read-only for the app, so there it defaults to %APPDATA%\PMDir; when that fallback happens, the Settings page tells you so directly.

After each successful start, the app keeps one local backup copy of the database under ~/.pmdir/<library name>/, so a corrupted library can be recovered. It is a local copy — it is not uploaded anywhere.

3. Capabilities PMDir deliberately does not have

  • The database is not encrypted. It is an ordinary local database file, so anyone who can read that file can read the file names and paths inside it. Keep your data directory under your own account, or protect it with full-disk / volume encryption (for example BitLocker).
  • No cloud sync, no remote locate, no remote wipe. Moving to another computer means copying the data directory yourself.
  • PMDir never uploads or transmits your actual files. Deletion goes through the system Recycle Bin, not over a network.

4. The password you type for a protected archive

When you open or extract a password-protected archive, PMDir asks for the password at the step that needs it. That password is used for that operation only — it is not stored in the database and not written to the logs.

5. Third-party components and your system

PMDir is built on a number of open-source components (UI framework, database engines, full-text search, archive and legacy document-format readers). The complete list with each licence is on the Acknowledgements page inside the app and in THIRD_PARTY_NOTICES.txt next to the program. All of them run on your machine and none of them reports data anywhere because of PMDir.

Two facts that involve your system rather than PMDir, stated plainly: the Microsoft Store itself checks for app updates and validates licences, and PMDir's interface is rendered by the WebView2 runtime that Microsoft maintains and may update on its own. Both happen at the operating-system level, are not initiated by PMDir, and do not involve any of your PMDir data.

6. How to remove everything

Uninstalling PMDir never touches your own files. What it may leave behind is the database, the index, the logs and the backups. Microsoft Store edition: the Store does not run our uninstaller, so to clear everything delete these two locations by hand: 

%APPDATA%\PMDir          database (data\meta.sqlite), full-text index, logs
%USERPROFILE%\.pmdir     the per-library pre-start backups

Portable edition: delete the program folder. Installer (NSIS) edition: the uninstaller asks whether to keep the backups and removes the backup tree under ~\.pmdir; if you pointed the data directory somewhere else, delete that location yourself.

Once those directories are gone, nothing about you remains — we never kept a copy in the first place.

7. Changes to this policy

The date at the top of this page is its version. If the policy changes we will update this page. Because PMDir does not use the network, it cannot and will not show you a "policy updated" notice — please come back and check when you need to.
